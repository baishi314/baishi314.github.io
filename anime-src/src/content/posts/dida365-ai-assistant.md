大学里丢的分，很少丢在不会做上，多半丢在"没看见"和"忘了"上。班群一条"周三下午三点交实验报告"，你当时点了"收到"，两小时后就只记得自己点过收到。

我想解决的不是"记性差"，而是**入口太散**：通知在 QQ 群、课表在教务系统、作业在作业帮、班委的要求在私聊、社团的安排在文档。人脑不适合当这种多源消息的总线。

最后跑通的方案很简单——**只留一个清单入口，其余全交给 AI 往里写**。这篇是完整落地记录：滴答清单怎么整理、五个 AI 平台各自怎么接、给 AI 的规则文档怎么写、`create_task` 的每个参数是什么。

## 一、先说最后跑成什么样

一句话：**手机上只有一个清单叫「我的任务」，我从不主动打开它，靠通知来叫我；往里写任务的是 AI，不是我。**

| 项 | 值 |
|---|---|
| 清单工具 | 滴答清单（Dida365 / TickTick），免费版够用 |
| 清单数量 | **就一个**：`我的任务`（唯一入口，不再按科目分清单） |
| 输入方式 | 把 QQ 群消息转发给 AI（我日常用的是 dsh / Claude / Codex 任一） |
| 提醒 | 每个硬截止任务 **提前 1 天 + 提前 1 小时** 双提醒 |
| 重复 | 例行事项 `RRULE:FREQ=WEEKLY;INTERVAL=2`（每两周） |
| 时区 | 全部 `Asia/Shanghai` |
| 完成动作 | 打勾 → `update_task(status: 2)` |

整套东西的收益不是"记得更多"，是**不再需要记得**：临期有提醒、冲突有人（AI）先替你列出来。

## 二、为什么是滴答清单

把选型过程压缩成一张表，标准就四条：手机能不能强提醒、有没有开放 API、重复规则够不够强、免费版能不能用。

| 方案 | 结论 |
|---|---|
| 滴答清单 | ✅ 选了。安卓/iOS 都有、强提醒到位、**官方开放平台有完整 REST API**、重复规则支持原生 RRULE、免费版覆盖个人使用 |
| 系统自带待办 | 提醒弱、没有 API，AI 写不进去，直接出局 |
| Notion / 飞书多维表格 | 能存不能提醒，手机上永远想不起来看，出局 |
| 纯自建（日历 + 脚本） | 维护成本大于收益，排除 |
| 非官方第三方 API 套壳 | 随时失效，排除 |

关键的一条是**开放平台**：滴答清单把任务读写做成了标准 REST 接口，这件事才让"AI 替我建任务"从幻想变成几十行配置。

而且必须说清一个认知，这是后面所有配置的前提：

> **AI 连的是你的云端账号，不是你的手机。**

滴答清单的数据在 TickTick 账号的云端。所以 AI 在电脑上建的任务，你手机上几秒后就能收到提醒——**中间不需要手机在线、不需要同一局域网、不需要任何投屏或远程控制**。搞清这一点，剩下的全是配置活。

## 三、准备工作：先把清单整理成 AI 能写的样子

AI 往一个乱的清单里写东西，结果只会比手写更乱。所以先做三件小事，十分钟。

**1）装 App，注册账号。** 手机装官方 App（安卓/iOS 都有），用手机号注册。**用国服账号（dida365）最稳**——国际版 TickTick 的 API 域名和国服不同，混用会出一堆 401。

**2）只建一个清单，叫「我的任务」。** 别按科目分清单。分清单是给人看的，AI 写任务时需要先判断"该写进哪个清单"，这一步判断就是错误来源。**单一入口 + 靠优先级和提醒区分**，是对机器更友好的结构。

**3）建任务时按固定模板填。** 手动建任务五步，顺序别变：

1. **标题**：`什么事 + 截止时间 + 谁负责`（例：`交计组实验报告 · 周三 15:00 前 · 我`）
2. **日期**：填截止那天，别填"今天"
3. **提醒**：加两条 —— 提前 1 天、提前 1 小时（提前 1 天给"能改计划"的余量，提前 1 小时给"现在就做"的推力）
4. **重要性**：考试、提交、打卡类打红旗（对应 `priority: 5`）
5. **保存**

这五步后来变成了我给 AI 的规则，一字不改。**人的操作习惯先定下来，AI 才能模仿。**

## 四、提醒怎么设：提前量是有公式的

我一开始的错是"所有任务提前 1 小时提醒"。结果：跨校区开会，1 小时前才响，路上就要 40 分钟。提醒不是越晚越紧迫，是**要覆盖住赶路的时间**。

现在的规则：

| 任务类型 | 提醒提前量 |
|---|---|
| 硬截止（交作业、考试、报名、打卡） | 提前 **1 天** + 提前 **1 小时** |
| 到场集合（开会、班会、活动签到） | 提前 **20 分钟**（校内换场地 + 步行时间） |
| 跨区 / 出校 | 在上一行基础上**再多 15 分钟** |
| 远期大任务（竞赛报名、论文、实习投递） | 提前 **1 个月**先响一次，让你开始 |
| 例行事项（值日、周报、团课） | 每 **两周**重复，固定周三 |

原则就一句：**宁可早到，不要卡点。** 早到十分钟只是多刷会手机，卡点误一次是实打实的损失。

## 五、五个平台怎么把 AI 接到账号上

这里是全文最实操的部分。**各家思路完全一样**：拿到一个能访问滴答清单的 MCP server（或 API 凭据），把它挂进你常用的 AI 客户端。差别只在配置文件叫什么叫在哪。

先看总览：

| 平台 | 接入方式 | 适合谁 |
|---|---|---|
| **WorkBuddy** | 左侧「+」→ 连接器 → TickTick OAuth 授权，`dida365` MCP 直接可用 | 想零配置、要图形界面的人 |
| **DeepSeek / dsh** | 自定义智能体 + 函数调用，或挂 MCP 网关 | 已经在用 dsh 干活的人 |
| **Codex / ChatGPT** | `mcp.json` 加 server；或自定义 GPT 用 Actions 调 API | 习惯终端和 IDE 的人 |
| **Claude** | `claude_desktop_config.json` 里 `mcpServers` 加一项 | 桌面端重度用户 |
| **Cursor / Windsurf** | 设置里加 MCP，再把规则写进项目规则文件 | 边写代码边管日程的人 |

### 5.1 WorkBuddy：唯一一个不用碰配置文件的

左边栏「+」→ **连接器** → 找 TickTick → 点授权 → 浏览器里登一次滴答清单账号，OAuth 走完就通了。通了之后 `dida365` 这个 MCP 就是可用状态。

接着做两件提升体验的事：

- **建一个专属专家/助理**，把我的规则文档（第七节那份）整篇作为系统提示贴进去。这样它不用每次重新理解"什么叫提前量"。
- **设一条定时自动化**：每天早上 8 点，拉一遍未完成任务，筛出未来 7 天内的和打了红旗的，推给我。

这两步做完，它就从"能调接口的工具"变成"每天早上替我巡视一遍的助理"。

### 5.2 DeepSeek / dsh：自定义智能体 + 函数调用

dsh 里两条路，选一条就行：

**路 A：自定义智能体 + 函数调用。** 去滴答清单开放平台申请应用，拿到 `client_id` / `client_secret`，换 access token，然后把「建任务 / 查清单 / 改状态」三个接口包成函数给模型调用。

**路 B：MCP 网关。** 挂一个 `dida365-mcp` 的 server，模型直接看到工具，不用自己写函数。开源实现有好几个，我用的是 [`Xrondev/mcp-dida365`](https://github.com/Xrondev/mcp-dida365)（功能覆盖比较全，支持 Dida365 国服），另一个可选的是 [`yidianyiko/ticktick-mcp-v2`](https://github.com/yidianyiko/ticktick-mcp-v2)（走 v2 API，性能更好）。

**路 C（不写代码）：Dify。** 拖拽搭一个 agent，把滴答清单的 HTTP 接口当工具节点连上，适合完全不想碰终端的人。

⚠️ **token 是你的账号密码级别凭据**，别贴进公开仓库、别发群里。我把它放本地 `.env`，`.gitignore` 里第一行就是它。

### 5.3 Codex / ChatGPT：mcp.json

在配置目录建（或编辑）`mcp.json`，加一个 server：

```json
{
  "mcpServers": {
    "dida365": {
      "command": "npx",
      "args": ["-y", "mcp-dida365"],
      "env": {
        "DIDA365_CLIENT_ID": "你的_client_id",
        "DIDA365_CLIENT_SECRET": "你的_client_secret",
        "DIDA365_ACCESS_TOKEN": "你的_access_token"
      }
    }
  }
}
```

ChatGPT 网页版没有本地 MCP，走**自定义 GPT + Actions**：把开放平台的 OpenAPI schema 贴进 Actions，鉴权选 API Key。功能一样，就是配起来麻烦些。

### 5.4 Claude：claude_desktop_config.json

Claude 桌面端读的是 `claude_desktop_config.json`，结构同上，键名是 `mcpServers`：

```json
{
  "mcpServers": {
    "dida365": {
      "command": "npx",
      "args": ["-y", "mcp-dida365"],
      "env": { "DIDA365_ACCESS_TOKEN": "你的_access_token" }
    }
  }
}
```

改完**必须完全退出 Claude 再重开**（托盘里也要退），配置只在启动时读一次。

不想配 MCP 的话有个土办法：建一个 Project，把第七节那份规则文档丢进去当项目知识，让它输出**格式化好的任务文本**，你再手动粘贴。半自动，但零配置。

### 5.5 Cursor / Windsurf

设置里找到 MCP，配置格式和 5.3 一样。再把规则写进 `.cursorrules`（Cursor）或项目规则文件（Windsurf）：

```
处理任何日程类信息时：先提取 事/时间/地点/负责人/特殊要求，
缺的字段留空并明确说明缺什么；再调用 dida365 建任务；
硬截止任务加两条提醒 TRIGGER:-P1D 和 TRIGGER:-PT60M；时区 Asia/Shanghai。
```

## 六、把规则写成文档交给 AI（这段可以直接抄）

平台配好只是"能连上"。真正决定好不好用的是**你给 AI 的那份规则**。我的版本，整段复制进系统提示就行：

> **建任务规则**
>
> 1. 标题格式：`什么事 + 截止时间 + 谁负责`
> 2. 硬截止任务：提前 1 天 + 提前 1 小时，两条提醒都要
> 3. 到场集合类：提前 20 分钟
> 4. 远期大任务（报名/论文/投递）：提前 1 个月先提醒一次
> 5. 例行事项：每两周重复
> 6. 收到新消息就入清单，不要等；临期主动提醒，不要等我问

> **操作细则**
>
> 1. **先提取信息**：事、时间、地点、负责人、特别要求。缺的留空，并明确告诉我缺什么
> 2. **再建任务**：写进「我的任务」清单，备注里写清地点 / 注意点 / 来源（哪个群、谁说的）/ 关联事项
> 3. **按紧急度设提醒**（见上）
> 4. **重复任务**用 `repeatFlag` 配
> 5. **重要度**：考试、提交、打卡 → `priority 5`（红旗）
> 6. **留提前量**：校内换场地按 20 分钟算，跨区再多 15 分钟，宁可早到
> 7. **每次对话开头**先看一遍未来 7 天的临期任务和红旗任务，主动提醒我
> 8. **发现冲突**（两个任务时间撞了）先列出冲突点让我拍板，不要自己改时间
> 9. 我说"做完了"，你打勾（`status: 2`）

第 8 条是我被坑过才加的。有一次它"贴心"地把我两个撞车的会挪开了一个，结果我按老时间去了空会议室。

## 七、技术细节：create_task 到底怎么填

如果你用的是 MCP 方案，工具就那几个，参数如下（以滴答清单开放平台为准，界面会变，以官方文档为最终依据）。

| 工具 | 作用 |
|---|---|
| `list_projects` | 列出所有清单，**拿到清单 id 的第一步** |
| `create_project` | 建清单（`name` / `view_mode: list` / `kind: TASK`） |
| `get_project_with_undone_tasks` | 拉某清单里所有未完成任务（每天早上巡检用这个） |
| `search` | 全文搜任务 |
| `create_task` | 建任务，主力工具 |
| `update_task` | 改任务；`status: 2` 表示完成 |

`create_task` 的关键参数：

| 参数 | 说明 | 例 |
|---|---|---|
| `projectId` | **必填**。先 `list_projects` 查 | `inbox123456` |
| `title` | 标题 | `交计组实验报告 · 周三 15:00 前` |
| `content` | 备注：地点、注意点、来源 | `实验楼 B302，交纸质版，来源：计组群` |
| `dueDate` | ISO 时间，**带时区偏移** | `2026-11-04T15:00:00+0800` |
| `isAllDay` | 是否全天 | `false` |
| `timeZone` | 时区 | `Asia/Shanghai` |
| `priority` | `0` 无 / `1` 低 / `3` 中 / `5` 高（红旗） | `5` |
| `reminders` | 提醒数组，ISO 8601 时长 | `["TRIGGER:-P1D", "TRIGGER:-PT60M"]` |
| `repeatFlag` | 重复规则 | 见下 |

`repeatFlag` 三个高频写法：

```
RRULE:FREQ=DAILY                              # 每天
RRULE:FREQ=WEEKLY;INTERVAL=2;BYDAY=TU;COUNT=4 # 每两周的周二，共 4 次
ERULE:NAME=CUSTOM;BYDATE=20261125,20261130    # 指定几个具体日期
```

第一次配置的完整顺序：

1. `list_projects` → 看有没有「我的任务」，记下它的 id
2. 没有就 `create_project`（`name: 我的任务`, `view_mode: list`, `kind: TASK`）
3. 之后每次 `create_task` 都把那个 id 塞进 `projectId`

`.env` 里长这样：

```bash
DIDA365_CLIENT_ID=xxxx
DIDA365_CLIENT_SECRET=xxxx
DIDA365_ACCESS_TOKEN=xxxx
DIDA365_BASE_URL=https://api.dida365.com/open/v1
```

## 八、踩过的坑

**没连上 MCP 就开始编任务。** 最贵的一次错误：它没拿到工具权限，直接凭对话内容"生成"了三条任务并告诉我"已建好"。一条都没进清单，我按它说的时间去交材料，白跑一趟。

> 规则：**没有工具返回结果，就不要声称操作成功。**没连上就直说没连上。

**时区没写。** `dueDate` 不带 `+0800`，服务器按 UTC 存，任务会显示在半夜三点。所有时间统一 `Asia/Shanghai`，没有例外。

**国服国际版混用。** API 域名不同，混着配就是一路 401。用国服账号就全套用 `api.dida365.com`。

**让 AI 自己决定写进哪个清单。** 一分清单它就开始分类，分错就是找不到。单一清单，靠 `priority` 和 `dueDate` 区分，稳得多。

**它擅自"优化"我的时间。** 见第六节第 8 条。冲突先报，不许自己拍板。

**规则文档太长。** 一开始我把整本手册塞进系统提示，它反而抓不住重点。最后砍到上面那十几条，效果好得多。

## 九、这套东西到底省了什么

不是省了"记"的力气，是省了**每天几十次"我得记住这件事"的心理占用**。

消息进来 → 转发给 AI → 它提取、建任务、设提醒 → 完事，我不再需要把这件事挂在工作记忆里。到了该做的时候，手机响。

真正的转折点是"**清单变成唯一入口**"那天：我不再在群里翻聊天记录找截止时间，不再在三个 App 里各存一半的事。所有事的真相，都在同一个清单里。

相关链接我收进**本站的资源导航页**了，新加了一栏「⏰ 时间管理 & 日程」：滴答清单官网、[滴答清单开放平台](https://developer.dida365.com/)、帮助中心、两个开源的 MCP server 实现，还有 [WorkBuddy 文档](https://www.workbuddy.cn/docs/)。七条全实测能打开。

如果你也打算试，建议就从这个顺序开始：**装 App → 建一个清单 → 手动按五步建三个任务 → 再把规则交给 AI**。手动那三个任务很关键，它是你给 AI 的样例。
